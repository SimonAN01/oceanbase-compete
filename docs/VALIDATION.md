日期：2026-10-27（Asia/Shanghai）。本文件不包含真实账号、Cookie、队伍信息、私有仓库地址、提交 SHA、任务编号或完整榜单。实时运行数据留在使用者本地状态目录。

## 验证方法

自动化检查使用标准库 unittest、虚构服务和模拟 HTTP。真实接口检查只读取必要的身份、赛题、任务和榜单，以及前端同样使用的报名仓库回填和实践验证行接口。本轮没有发送新的评测提交请求。

| 功能 | 自动化验证 | 本轮真实接口验证 |
|---|---|---|
| 登录检查 | 匿名 HTTP 成功不等于登录、过期状态、输入格式与脱敏 | 身份接口成功识别登录态 |
| 比赛、赛题及配置 | 目标绑定、题目/仓库错配、未知字段/模式 | 四个内置目标均与实时 submissionOptions、报名仓库对应 |
| 提交前检查 | 完整 SHA、分支格式、远端 tip/历史祖先、关闭窗口、材料格式 | 核实用户指定的已推送 CSV 基线；dry-run 通过，未提交未推送增强 |

## 与真实新提测的区别

模拟服务验证了写入、等待、回执和队列状态机的各分支；已有真实任务验证了账号、目标、版本、查分和重复保护的接口关联。这两种证据均不应被表述为“本轮新提交已评测成功”。

本轮没有重新评测已经失败的 CSV 基线，也没有把未推送的增强当作提交对象。真实新写入和新任务成功评分、真实平台网络故障下的恢复尚未在本轮重演。后续对明确的新版本执行时，工具仍须以服务端受理和回读的唯一任务为依据。

## 已识别并加入回归检查的实际差异

1. Cookie 偏好项 `receive-cookie-deprecation=1` 不能被视为认证值，否则全局脱敏会破坏含数字 1 的任务 ID/commit；现在只提取认证键的凭证值并回归验证。
2. 榜单 total/pageNum 是当前页包装信息，不能用第一页面宣称全量。短末页后继续查询还可能得到 code=508；现在按请求的分页边界判断末页，业务错误始终是错误，不吞成空页。
3. 失败任务可带有 `strMachineScore=0.000`；状态必须优先，失败不产生数值成绩。
4. 标准 Decimal 上下文会限制运算精度；分数差值使用输入规模确定的局部上下文，避免把保留原精度的分数再次舍入。

## 可复现检查

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
python skills/oceanbase-compete/scripts/obcomp.py --version
python install.py --skills-dir /path/to/test-skills
```

GitHub Actions 覆盖 Linux、macOS、Windows，以及 Python 3.10、3.12、3.14。源码中的测试数据均为虚构数据。测试通过不等于已验证新的官网协议、未适配赛题或任意材料的有效性。
